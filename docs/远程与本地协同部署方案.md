# 远程服务与本地客户端协同部署方案

## 一、方案背景

在实际工程实践中，用户通常拥有本地开发机（笔记本/台式机，拥有最舒适的本地开发环境）与云端服务器（高带宽、公网 IP、全天候在线）。

本方案系统性梳理如何将 **本地电脑上的开发流** 与 **云端部署的 CloudCLI 平台** 高效结合。

---

## 二、四种协同模式与实施路径

### 模式一：本地同机宿主模式（最轻量、零延迟）

- **原理**：CloudCLI 采用“同机发现”机制。直接在本地电脑运行 CloudCLI，它会自动扫描并呈现本地电脑上的会话与项目。
- **实施步骤**：
  在本地终端执行：
  ```bash
  npx @cloudcli-ai/cloudcli
  ```
  或者下载安装官方原生桌面客户端（GitHub Releases 中的 `.dmg` 或 `.exe`）。
- **优势**：
  - 本地文件实时保存无网络延迟。
  - 直接读取本地 `~/.claude`、`~/.cursor`、`~/.gemini`。

---

### 模式二：云端中心 + Git 流水线协同（推荐全天候开发）

- **原理**：将云端服务器作为**“AI 员工工位”**，本地电脑作为代码合并与审核终端。
- **实施步骤**：
  1. 在云端平台的 **Settings -> GitHub Credentials** 绑定 GitHub Token。
  2. 本地电脑编写的代码正常 `git push` 到 GitHub 仓库。
  3. 当需要大规模重构、修 Bug 或编写单元测试时，在云端平台直接触发任务（或通过 `POST /api/agent` 调用）：
     ```json
     {
       "githubUrl": "https://github.com/your-org/your-repo",
       "message": "按照最新设计规范优化鉴权中间件并补充测试",
       "createBranch": true,
       "branchName": "feature/auth-refactor",
       "createPR": true
     }
     ```
  4. 云端智能体自动完成代码修改并提交 PR，本地电脑直接拉取分支审查合并。

---

###模式三：安全反向穿透模式（手机/外出远程控制）

- **原理**：本地电脑运行 CloudCLI，配合穿透工具映射一个固定公网安全域名。
- **实施步骤**：
  - **选项 A（Cloudflare Tunnel，极力推荐）**：
    ```bash
    cloudflared tunnel --url http://localhost:3001
    ```
    即可生成一个带免费 SSL 证书的永久 HTTPS 域名，手机随时打开。
  - **选项 B（Tailscale / WireGuard）**：
    手机与本地电脑加入同一个虚拟专网，使用内网 IP 访问。

---

### 模式四：SSHFS / 远程磁盘直连

- **原理**：将本地工作区或者远程服务器的工作区通过网络文件系统透明挂载。
- **实施步骤**：
  通过 `sshfs` 将本地目录挂载到云端服务器供 Agent 操作：
  ```bash
  sshfs user@local-ip:/path/to/project /home/yubs/workspace/project
  ```
  云端 CloudCLI 即可直接视其为本地项目进行实时修改。

---

## 三、当前云端环境运维参考

云端服务已配置为标准的 systemd 托管后台服务：

- **服务名**：`cloudcli.service`
- **监听端口**：`0.0.0.0:3001`
- **公网地址**：`http://japan.bleem.site:3001/`
- **常用管理命令**：
  ```bash
  # 查看运行状态
  sudo systemctl status cloudcli.service

  # 查看实时日志
  sudo journalctl -u cloudcli.service -f

  # 重启服务
  sudo systemctl restart cloudcli.service
  ```
